SSA 形式

SSA（Static Single Assignment，静态单赋值）是一种 IR 形式， 其核心约束是：每个变量在程序中只被赋值恰好一次。 这使得数据流分析变得显式且简单，是现代编译器优化的基础。

为什么需要 SSA

在非 SSA 形式中，同一个变量可能被多次赋值，分析时必须追踪"哪个赋值影响了哪个使用"。 在 SSA 形式中，每次赋值产生一个新版本的变量，每个使用点明确知道值的来源。

非 SSA 形式

int x = 1;
int y = 2;
x = x + y;    // x 被重新赋值
y = x + 1;    // y 被重新赋值

SSA 形式

x1 = 1
y1 = 2
x2 = x1 + y1
y2 = x2 + 1

每个变量只赋值一次。x2 的使用者无需分析即可确定它来自第三条语句， 数据流关系一目了然。

Phi 节点

当控制流汇合时（如 if-else 的两条分支），同一个变量可能来自不同分支的不同赋值。 SSA 使用 phi 节点 来在汇合点选择正确的值。

原始代码

int x;
if (cond) {
    x = 1;
} else {
    x = 2;
}
// 此处 x 的值取决于走哪条分支
print(x);

SSA 形式

br cond, then_bb, else_bb

then_bb:
  x1 = 1
  br merge_bb

else_bb:
  x2 = 2
  br merge_bb

merge_bb:
  x3 = phi(x1 from then_bb, x2 from else_bb)
  call print(x3)

phi 指令根据控制流从哪个前驱块进入，选择对应的值： 若从 then_bb 进入，x3 = x1 = 1； 若从 else_bb 进入，x3 = x2 = 2。

循环中的 Phi

Phi 节点在循环中同样扮演关键角色，用于合并循环初始值和循环体内的更新值：

int sum = 0;
int i = 0;
while (i < 10) {
    sum = sum + i;
    i = i + 1;
}
print(sum);

SSA 形式

entry:
  br cond_bb

cond_bb:
  sum1 = phi(sum0=0 from entry, sum2 from body_bb)
  i1   = phi(i0=0 from entry, i2 from body_bb)
  cond = icmp lt i1, 10
  br cond, body_bb, exit_bb

body_bb:
  sum2 = add sum1, i1
  i2   = add i1, 1
  br cond_bb

exit_bb:
  call print(sum1)

循环头 cond_bb 处的 phi 节点将入口的初始值（sum0=0） 与循环体回传的值（sum2）合并。每次迭代中，phi 选择来自 body_bb 的更新值。

SSA 的优势

优势说明
Use-Def 链显式化每个使用点的值来源唯一确定，无需复杂的 reaching definition 分析
简化死代码消除若某变量的定义没有被任何使用引用，直接删除即可
常量传播若某变量只被赋值为常量，所有使用点可直接替换为该常量
全局值编号相同的计算表达式可以统一为同一个值编号
寄存器分配SSA 的活性分析更精确，减少不必要的寄存器压力

本项目中的 SSA

IR 生成阶段（GenIR）产生的 IR 使用 alloca → store → load 模式， 变量以内存地址形式存在，不是 SSA。 

// GenIR 产生的初始 IR（非 SSA）
%0 = alloca i32           // 分配 x
store i32 1, i32* %0      // x = 1
%1 = load i32, i32* %0    // 读取 x
%2 = add i32 %1, 2
store i32 %2, i32* %0     // x = x + 2（覆盖同一个 alloca）

Mem2Reg Pass 将 alloca/load/store 提升为 SSA 寄存器形式， 在控制流汇合点插入 phi 节点： 

// Mem2Reg 后的 SSA 形式
x1 = 1
x2 = add x1, 2

具体的 Mem2Reg 实现（包括 SROA 预处理、phi 插入、rename 算法） 将在优化 Pass 章节中详细说明。
