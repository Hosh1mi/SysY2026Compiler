依赖分析

依赖分析判断两次内存访问之间是否存在数据依赖，以及依赖的方向。 它是循环交换（loop interchange）、向量化等变换的正确性基础。

三个协作模块

依赖分析由三个模块协作完成：

模块职责输出
AffineAnalysis把 Value 表达为关于规范 IV 的仿射表达式\(c_0 + \sum c_i \cdot iv_i\)
DependenceAnalysis对访问对做 GCD test，求方向向量direction[i] ∈ {=, <, >, *}
CostModel估算 GEP 在某 IV 上的字节 stridestrideAlong(gep, iv)

AffineAnalysis — 仿射表达式

将 IR 中的 Value 表达成关于循环归纳变量的仿射形式 \(c_0 + \sum c_i \cdot iv_i\)。 支持常数、规范 IV、加减法、常数乘法。

示例：二维数组索引

// 源代码
int a[100][100];
for (int i = 0; i < 100; i++)
    for (int j = 0; j < 100; j++)
        a[i][j] = a[i][j-1] + 1;

GEP 的两个索引对应的仿射表达式：

// a[i][j] 的 GEP 索引
idx₀ = i        →  AffineExpr { constant=0, coeffs={iv_i: 1} }
idx₁ = j        →  AffineExpr { constant=0, coeffs={iv_j: 1} }

// a[i][j-1] 的 GEP 索引
idx₀ = i        →  AffineExpr { constant=0, coeffs={iv_i: 1} }
idx₁ = j - 1    →  AffineExpr { constant=-1, coeffs={iv_j: 1} }

接口

class AffineExpr {
    int                      constant = 0;
    std::map<PhiInst *, int> coeffs;   // iv → coefficient
    bool                     valid    = true;

    bool isConstant() const;
    int  coeffOf(PhiInst *iv) const;
};

class AffineAnalysis {
    AffineExpr analyze(Value *v);  // 主入口
};

DependenceAnalysis — 方向向量

对一对内存访问 (acc1, acc2)，在共同嵌套的循环中求方向向量。 方向 direction[i] 描述从 acc1 到 acc2 在第 i 层循环的迭代方向关系。

方向含义示例
=同一迭代中访问a[i] = a[i] + 1
<acc1 在更早的迭代a[i] = a[i-1] + 1（流依赖）
>acc1 在更晚的迭代a[i-1] = a[i] + 1（反依赖）
*无法精确判断非仿射索引，保守返回

GCD Test

对每一维索引计算差值 \(\text{diff} = c_{\text{const}} + \sum c_{iv} \cdot iv\)。 若 gcd(c_iv) 不整除 c_const，则该维无依赖 → 整对独立。 

// 示例：a[i][j] vs a[i][j-1]
// 维 0: diff = i - i = 0              → direction[0] = '='
// 维 1: diff = j - (j-1) = 1          → 常数 1 ≠ 0
//        gcd() = 0 不整除 1 → 无依赖？不对，这里 diff 是纯常数 1
//        纯常数非零 → direction[1] 可判定：acc1 的 j 总在 acc2 的 j-1 之后 → '>'
// 方向向量: (=, >)  — 反依赖，i 同层，j 方向相反

接口与结果

struct Result {
    bool             aliased  = false;            // 可能命中同一地址？
    bool             provably_independent = false; // 已证明无依赖
    std::vector<Dir> direction;                  // 每层方向（最外在前）
    std::vector<Loop *> commonLoops;             // 共同嵌套的循环
};

class DependenceAnalysis {
    Result test(Instruction *acc1, Instruction *acc2);
    bool isInterchangeLegal(Loop *outer, Loop *inner,
                            const std::vector<Instruction *> &accesses);
};

完整示例：循环交换判定

// 源代码：行优先遍历
int a[N][N];
for (int i = 0; i < N; i++)        // outer
    for (int j = 0; j < N; j++)    // inner
        a[j][i] = a[j][i-1] + 1;   // 注意：按列访问，cache 不友好

分析 a[j][i]（store）与 a[j][i-1]（load）：

// AffineAnalysis:
//   store idx₀ = j  → {iv_j: 1}        load idx₀ = j   → {iv_j: 1}
//   store idx₁ = i  → {iv_i: 1}        load idx₁ = i-1 → {iv_i: 1, constant: -1}

// DependenceAnalysis:
//   维 0 (j): diff = j - j = 0          → direction[0] = '='
//   维 1 (i): diff = i - (i-1) = 1      → direction[1] = '>' (纯常数非零)
//   方向向量: (=, >)

// isInterchangeLegal(outer=i, inner=j):
//   direction = (=, >)
//   交换后变为 (>, =)，原始依赖方向被反转？
//   检查：原 (pos_outer, pos_inner) = (0,1)，方向 (=, >)
//         交换后方向向量变为 (>, =)
//         第一维出现 '>' → 依赖被反转 → 交换不合法！

结论：这个循环不能交换。因为原始代码存在 i 方向的反依赖。

CostModel — Cache 代价估算

当循环交换合法时，CostModel 估算交换前后的 cache 友好度变化。 对每个 GEP 计算内层 IV 步进 1 时的字节 stride。 

// 行优先数组 int a[100][100]，元素 4 字节
// a[i][j]：内层 j 步进 1 → stride = 4 字节（连续访问 ✓）
// a[j][i]：内层 j 步进 1 → stride = 400 字节（跨行访问 ✗）

class CostModel {
    long strideAlong(GetElementPtrInst *gep, PhiInst *iv);
    long totalStride(const std::vector<GetElementPtrInst *> &geps, PhiInst *iv);
};

// 循环交换收益 = Σ [stride_before(acc) - stride_after(acc)]
// gain > 0 → 交换后内层 stride 更小 → cache 更友好
