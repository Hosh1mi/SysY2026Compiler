寄存器分配

基于 Chaitin-Briggs 乐观图着色算法的寄存器分配器。将 SSA Value 映射到 ARM64 物理寄存器，通过活跃区间分析、干扰图构建和溢出代价启发式，最小化栈槽访问。

概览

Arm64RegAlloc 接收 IR Function*，经过 10 个阶段产出 Value* → 物理寄存器名 的映射。未分配到寄存器的值留在栈槽中，由 Load/Store 子系统处理。

算法阶段

1. RPO 块序与前驱映射

对基本块进行 DFS 后序遍历并反转，得到逆后序（RPO）。这个顺序保证了活跃变量分析的收敛速度。同时构建每个块的前驱列表。

2. Leaf 函数参数预着色

对于不包含 Call 指令的 leaf 函数，参数可以预着色到对应的 ABI 寄存器：

// 整数参数 → w0~w7（或 x0~x7 对于指针）
// 浮点参数 → s0~s7
// 前 8 个同类参数可直接预着色
if (isLeaf) {
    int intArgIdx = 0, floatArgIdx = 0;
    for (auto arg : func_->arguments_) {
        if (isAllocatableFloatValue(arg->type_)) {
            if (floatArgIdx < 8)
                assignedRegs_[arg] = "s" + std::to_string(floatArgIdx++);
        } else {
            if (intArgIdx < 8)
                assignedRegs_[arg] = (isPtr ? "x" : "w") + std::to_string(intArgIdx++);
        }
    }
}

3. 颜色→物理寄存器映射

根据函数是否为 leaf，选择不同的寄存器优先级策略：

寄存器类Leaf 函数优先级非 Leaf 函数优先级
整数 (w/x)caller-saved 优先 (0-7, 9)，然后 callee-saved (19-28)r9 优先，然后 caller (0-7)，然后 callee (19-28)
浮点 (s)caller-saved 优先 (0-7, 16)，然后 callee-saved (8-15)caller (0-7) 优先，r16，然后 callee (8-15)
NEON (v)v8-v15（callee-saved 范围）

预着色寄存器从可用颜色池中移除。crossesCall 的值强制分配到 callee-saved 寄存器。

4. 指令编号与活跃区间构建

遍历 RPO 序列中的每条指令，递增全局编号 idx。记录每个值的定义位置（defPos）和最后使用位置（lastUse）。

特殊处理：Select 指令会延长其 ICmp 操作数的活跃范围；ICmp+Select 融合模式跳过 ICmp 的独立分配。

5. 活跃变量分析

标准迭代数据流分析：

  • PHI 处理 — PHI 操作数在对应前驱块的 LiveOut 中额外加入（phiOut）
  • 传递方程 — LiveOut(bb) = ∪ LiveIn(succ)；LiveIn = use ∪ (LiveOut - def)
  • crossesCall 检测 — 反向扫描每个块，若值在 Call 后仍然活跃，标记为 crossesCall

6. 支配树与循环深度

通过迭代支配算法计算每个块的支配集。检测回边（bb 支配 succ）以计算循环嵌套深度，用于溢出代价加权。

7. PHI 亲和性

构建 PHI 节点的操作数与结果之间的亲和关系。具有亲和关系的值倾向于分配相同颜色，减少 PHI 拷贝的 mov 指令：

for (auto phi : bb->instr_list_) {
    for (int i = 0; i < phi->num_ops_; i += 2) {
        auto val = phi->get_operand(i);
        phiAffinity[phi].insert(val);
        phiAffinity[val].insert(phi);
    }
}

8. 溢出代价计算

每个值的溢出代价 = 各使用点所在循环深度的 20^depth 之和。循环越深，溢出代价越高，越倾向于保留在寄存器中。PHI 亲和组内取最大代价统一。

9. 图着色（Chaitin-Briggs）

将活跃区间按寄存器类分为整数/浮点/NEON 三个池，分别着色：

void colorPool(pool, colorToReg, isFloat, callerSaved, spillCost, phiAffinity) {
    // Simplify: 反复移除度数 < K 的节点入栈
    // 若无低度节点，选择 spillCost / (degree+1) 最小的节点作为潜在溢出
    // Select: 逆序出栈，选择不与邻居冲突的颜色
    //   - 优先选择 PHI 伙伴的颜色（亲和性偏向）
    //   - crossesCall 值跳过 caller-saved 颜色
}

干扰图构建

活跃区间按起始位置排序后，两两检查是否重叠（sorted[j].start < sorted[i].end）。重叠的区间之间存在干扰边，不能分配相同颜色。

示例

简单循环中的寄存器分配

// IR:
//   %sum = phi i32 [0, %entry], [%next, %loop]
//   %i = phi i32 [0, %entry], [%i1, %loop]
//   %next = add i32 %sum, %i
//   %i1 = add i32 %i, 1
//   %cmp = icmp slt i32 %i1, 100
//   br i1 %cmp, %loop, %exit

// 寄存器分配后（leaf 函数，无 callee-saved 需求）：
//   %sum → w2, %i → w3, %next → w2（与 %sum 复用，活跃区间不重叠）
//   %i1 → w4, %cmp → 不分配（与 Br 融合）
