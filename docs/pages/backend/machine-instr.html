MachineInstr

后端机器指令抽象层，将汇编文本解析为结构化指令对象，携带寄存器定义/使用、延迟、副作用等元数据，为寄存器分配、指令调度和 Peephole 优化提供统一接口。

概览

MachineInstr 是后端代码生成的核心数据结构。它不是传统意义上的"机器指令"（二进制编码），而是汇编文本的结构化表示——每条指令保留原始文本（text），同时附带解析出的操作码分类（MOpcode）、寄存器定义/使用集合、延迟估计和副作用标记。这使得后续的寄存器分配器、指令调度器和 Peephole 优化器能够在结构化数据上工作，而不需要反复解析文本。

操作码分类（MOpcode）

MOpcode 是一个枚举类型，将 ARM64 汇编指令分为 18 个大类：

枚举值含义典型指令
Unknown未识别回退分类
Label标签foo_0:
Directive伪指令.text, .word, .global
Comment注释// comment
Mov数据移动mov, movz, movk, sxtw, fmov
Alu算术/逻辑add, sub, and, orr, eor, lsl, asr
Mul乘法mul, madd, msub, mneg
Div除法sdiv, udiv, fdiv
Load加载ldr, ldur, ld1
Store存储str, stur, st1
PairLoad对加载ldp
PairStore对存储stp
Cmp比较（设置标志）cmp, cmn, fcmp, tst
FlagUse标志使用cset, csel, cneg, ccmp
Branch分支b, b.cond, cbz, cbnz
Call调用bl
Ret返回ret
Adr地址加载adrp, adr
NeonNEON 向量add v0.4s, ...

数据结构

MachineInstr

单条机器指令的结构化表示，携带以下元数据：

machine.hpp
struct MachineInstr {
    std::string text;              // 原始汇编文本，如 "\tadd w10, w11, w12"
    std::string opcodeText;        // 操作码文本，如 "add"
    MOpcode opcode = MOpcode::Unknown;

    std::set<std::string> defs;    // 定义（写入）的寄存器集合
    std::set<std::string> uses;    // 使用（读取）的寄存器集合

    bool mayLoad = false;          // 是否可能加载内存
    bool mayStore = false;         // 是否可能存储内存
    bool setsFlags = false;        // 是否设置条件标志（cmp, tst）
    bool usesFlags = false;        // 是否使用条件标志（cset, csel, b.cond）
    bool isCall = false;           // 是否为函数调用
    bool isBarrier = false;        // 是否为屏障（不可移动/不可删除）
    bool isLabelLike = false;      // 是否为标签/伪指令/注释
    int latency = 1;               // 延迟估计（时钟周期）
    int originalIndex = 0;         // 在函数中的原始顺序号
};

延迟模型

延迟估计用于指令调度器决定指令的重排顺序：

指令类别延迟说明
ALU（add, sub, and...）1单周期执行
Mov（mov, sxtw...）1寄存器间搬运
整数乘法（mul, madd...）3多周期流水线
浮点乘法（fmul）5浮点流水线更长
Load（ldr, ldp...）4访存延迟
浮点运算（fadd, fsub, fneg）4浮点 ALU
除法（sdiv, fdiv）12最慢指令

寄存器归一化

解析时会将 ARM64 寄存器名归一化为内部名称，方便 defs/uses 分析：

  • w10 / x10 → r10（整数寄存器，w/x 共享物理寄存器）
  • s5 / d5 / v5 → v5（浮点/向量寄存器，s/d/v 共享）
  • wzr / xzr → zr（零寄存器，不参与 defs/uses）
  • sp 保持不变

归一化确保了 add w10, w11, w12 和 add x10, x11, x12 产生相同的 defs={r10}, uses={r11, r12}。

操作数解析

采用"第一个操作数为 def，其余为 use"的规则（defFirstUseRest）：

add w10, w11, w12
defs = {r10}    // 第一个操作数是目标寄存器
uses = {r11, r12} // 其余操作数是源寄存器

特殊指令有定制规则：

  • Load（ldr）：第一个操作数 def，地址操作数 use
  • Store（str）：所有操作数都是 use（没有寄存器被写入）
  • PairLoad（ldp）：前两个操作数 def，第三个 use
  • Cmp：无 def，所有操作数 use，setsFlags=true
  • movk：目标寄存器同时是 def 和 use（部分写入）
  • Call / Ret / Branch：isBarrier=true，不参与重排

Barrier 标记

以下指令被标记为 Barrier，调度器和 Peephole 优化器不可跨越或移动它们：

  • 标签（Label）、伪指令（Directive）、注释（Comment）
  • 分支（Branch）、调用（Call）、返回（Ret）
  • 涉及 SP（栈指针）或 x30（链接寄存器）的指令

MachineBasicBlock / MachineFunction / MachineModule

三级层次结构组织整个程序的机器指令：

machine.hpp
struct MachineBasicBlock {
    std::string label;                    // 块标签，如 "func_0:"
    std::vector<MachineInstr> instrs;     // 块内指令序列
};

struct MachineFunction {
    std::string name;                     // 函数名
    std::vector<MachineBasicBlock> blocks; // 基本块列表
    int nextIndex = 0;                    // 指令序号计数器
};

struct MachineModule {
    std::vector<MachineInstr> lines;      // 模块级指令（全局变量、段声明等）
    int nextIndex = 0;
};

appendMachineInstr 自动按标签分割基本块：遇到 Label 类型指令时，如果当前块已有指令，则创建新块。

指令构造

parseMachineInstr（从文本解析）

解析一行汇编文本，自动分类操作码、提取寄存器、设置标志：

示例
// 输入: "\tadd w10, w11, w12"
// 输出:
//   text = "\tadd w10, w11, w12"
//   opcodeText = "add"
//   opcode = MOpcode::Alu
//   defs = {r10}, uses = {r11, r12}
//   latency = 1

// 输入: "\tldr w10, [x29, #-8]"
// 输出:
//   text = "\tldr w10, [x29, #-8]"
//   opcodeText = "ldr"
//   opcode = MOpcode::Load
//   defs = {r10}, uses = {r29}
//   mayLoad = true, latency = 4

MachineInstr::make（手动构造）

用于 codegen 阶段直接构造指令，跳过文本解析：

示例
MachineInstr mi = MachineInstr::make(
    "\tmadd w10, w8, w16, w11",
    MOpcode::Mul,
    /*defs=*/ {"w10"},
    /*uses=*/ {"w8", "w16", "w11"},
    /*latency=*/ 3
);

MachineEmitter

指令发射器，为 Arm64FuncContext 提供统一的指令发射接口：

machine.hpp
class MachineEmitter {
public:
    explicit MachineEmitter(MachineFunction &func);
    void emit(MachineInstr inst);            // 发射结构化指令
    void emitLine(const std::string &line);  // 发射文本行（自动解析）
};

Arm64FuncContext 通过 MachineEmitter 向 MachineFunction 中追加指令。codegen 过程中的所有 emitXxxMachine 方法最终都调用 emitter 的 emit。

Dump 调试输出

启用 --dump-machine-instr 选项时，dumpMachineFunction 输出完整的结构化调试信息：

dump 输出示例
=== MachineFunction: main ===
  BB0 [main_0:] (15 instrs)
    [0] Alu | text="	add w10, w11, w12" defs={r10} uses={r11, r12} lat=1
    [1] Load | text="	ldr w13, [x29, #-8]" defs={r13} uses={r29} lat=4 LOAD
    [2] Cmp | text="	cmp w10, w13" defs={} uses={r10, r13} lat=1 SETS_FLAGS
    [3] Branch | text="	b.lt main_2" defs={} uses={} lat=1 BARRIER USES_FLAGS
    ...

每行显示指令序号、操作码分类、原始文本、defs/uses 集合、延迟、以及所有副作用标志（LOAD/STORE/SETS_FLAGS/USES_FLAGS/CALL/BARRIER/LABEL_LIKE）。

代码生成流水线

MachineInstr 在后端代码生成中的完整流转：

  1. IR → MachineFunction：Arm64FuncContext::generate() 遍历 IR 指令，通过 MachineEmitter 发射 MachineInstr
  2. 指令调度：MachineScheduler 读取 defs/uses/latency/barrier 信息，重排指令以隐藏延迟
  3. Peephole 优化：peepholeOptimize 在 MachineFunction 上做模式匹配和替换
  4. MachineFunction → 文本：printMachineFunction 将每条指令的 text 字段拼接输出

示例

从 IR Add 指令到 MachineInstr

中端 IR 的 %r = add i32 %a, %b 经过 codegen 生成：

codegen 过程
// 1. 寄存器分配器已为 %a 分配 w11，%b 分配 w12，%r 分配 w10
// 2. emitInstruction(Add) 调用 emitMachineInstrLine:
emitMachineInstrLine(
    "\tadd w10, w11, w12",     // 汇编文本
    MOpcode::Alu,              // 操作码分类
    /*defs=*/ {"w10"},         // 定义寄存器
    /*uses=*/ {"w11", "w12"},  // 使用寄存器
    /*latency=*/ 1             // 延迟
);
// 3. 内部调用 MachineInstr::make，归一化寄存器名后存入 MachineBasicBlock
//    defs = {r10}, uses = {r11, r12}

常量乘法强度削弱

%r = mul i32 %a, 3 被优化为移位加法：

// 原始 IR:  %r = mul i32 %a, 3
// codegen 识别 factor=3 是 2^1+1 形式，生成：
//   add w10, w11, w11, lsl #1    (即 a + a*2 = a*3)
// 对应 MachineInstr:
//   opcode = MOpcode::Alu
//   defs = {r10}, uses = {r11}
//   latency = 1
// 比通用 mul 指令（latency=3）快 3 倍
