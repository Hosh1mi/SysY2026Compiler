New-Feat Prompt 模板

用于新功能开发场景的结构化 Prompt 模板。复制模板，填入具体信息后发送给 AI 助手。

使用方式

  1. 点击代码块右上角的 Copy 按钮复制模板
  2. 将 {{占位符}} 替换为实际信息
  3. 发送给 AI 助手

模板

# 新功能开发

## 1. 功能描述

**功能名称**: {{一句话概括，如"循环不变量外提"}}
**所属阶段**: {{前端 / 中端优化 / 后端代码生成}}
**触发条件**: {{该功能在什么条件下生效，如 -O1 开启、特定 IR pattern、特定指令类型}}
**预期效果**: {{对正确性和性能的影响}}

## 2. 实现约束

- **正确性优先**：不破坏现有测试
- **SSA 合法性**：若涉及中端 IR 变换，需保证 SSA 形式
- **目标架构**：Cortex-A53 CPU，优化应有利于顺序执行核心（短依赖链、低延迟指令、减少分支预测失败）
- **验证方式**：修复后在 Docker 容器中运行 `arm_performance.sh` 确认全部通过（`docker ps -a` 查看容器，`docker exec` 进入，不要使用 qemu）

## 3. 期望输出

1. **设计方案** — 数据结构 + 算法流程，自行判断在管线中的集成位置
2. **具体实现** — 代码修改（文件路径 + diff）
3. **受益用例** — 哪些测试用例预期获得性能提升

填写指南

第 1 节：功能描述

触发条件越具体，AI 助手的实现方案越精准。对于优化 Pass，建议描述目标 IR pattern 的形态特征（如"循环体内不依赖 PHI 节点的 store 指令"）。

第 2 节：实现约束

始终使用已运行的 Docker 容器（docker exec），不要启动新容器或使用 qemu 模拟。测试脚本位于 /test 目录，使用 arm_ 前缀的脚本（arm_functional.sh、arm_performance.sh），不要使用 final 后缀的版本。

第 3 节：期望输出

Cortex-A53 是顺序执行的 ARMv8 核心，偏好短依赖链、低延迟指令和紧凑的代码体积。集成位置由 AI 助手根据现有管线结构自行判断。
