快速开始

从零搭建开发环境到跑通第一个测试用例。

1. 搭建环境

项目使用 Docker 提供统一的开发环境，内置 Flex、Bison、CMake、GCC 等全部依赖， 避免本地工具版本差异导致的问题。

构建并启动容器

在项目根目录下执行：

docker build --platform linux/arm64 -t sysy-dev .
docker run -it --platform linux/arm64 -v $(pwd):/workspace sysy-dev
提示

推荐使用上述命令而非直接挂载源码，可以防止 Flex/Bison 生成文件中包含宿主机特定路径。

进入容器后，项目代码位于 /workspace 目录。

容器内置工具

工具用途
gcc / clang编译编译器本体 & 编译生成的汇编
flex / bison生成词法/语法分析器
cmake构建系统
gdb / gdb-multiarch调试
python3测试脚本依赖

2. 编译与运行

在容器内的 /workspace 目录下编译编译器：

mkdir build && cd build
cmake ..
make -j8

编译成功后会在 build/ 目录下生成 compiler 可执行文件。

重新编译

修改源码后只需在 build/ 目录下执行 make -j8 即可增量编译，无需重新 cmake。

生成 IR（-c 标志）：

./compiler -c -o out.ll ../test/functional/00_main.sy

生成 ARM64 汇编（-S 标志）：

./compiler -S -o out.s ../test/functional/00_main.sy

编译并运行汇编，链接运行时库 libsysy.a（提供 getint、putint 等 IO 函数）：

gcc out.s ../lib/libsysy.a -o out
./out
带输入的测试

如果测试用例有输入文件（.in），使用重定向：
./out < ../test/functional/38_op_priority4.in

3. 优化与调试

通过 -O 参数控制优化等级，配合调试标志排查问题：

标志说明
-O0无优化，直接生成代码（默认）
-O1启用全部中端优化 Pass + 后端寄存器分配、指令调度、Peephole
-O2在 -O1 基础上执行两轮完整优化流水线（调试用）
 
./compiler -O1 -S -o out.s ../test/functional/00_main.sy

编译器还提供以下调试标志：

标志作用
--dump-ir每个 Pass 前后 dump IR 到 stderr（输出极长，建议 2> dump.txt 重定向）
--verify-ir每个 Pass 后校验 IR 完整性（TODO：目前未实现）
--fno-peephole在 -O1 下禁用 Peephole 汇编后优化
--fno-schedule在 -O1 下禁用机器指令调度
--dump-machine-instr输出每个函数的机器指令详情（opcode、defs/uses、latency）到 stderr

常用调试命令

# dump 每个 Pass 的 IR 变化
./compiler -O1 -c test.sy --dump-ir 2> ir_dump.txt

# 查看后端机器指令细节
./compiler -O1 -S test.sy --dump-machine-instr 2> mi_dump.txt

# 禁用后端优化，排查是否是 Peephole/调度引入的问题
./compiler -O1 -S -o out.s test.sy --fno-peephole --fno-schedule

4. 批量测试

测试脚本位于 test/ 目录下，按环境和测试集分类：

ARM 原生环境（容器内直接运行）

cd ../test
./arm_functional.sh       # 功能测试
./arm_performance.sh      # 性能测试
./arm_performance_final.sh # 最终性能测试

AMD 交叉编译环境

./amd_functional.sh       # 需要 aarch64-linux-gnu-gcc + qemu-aarch64
./amd_performance.sh
./amd_performance_final.sh

测试结果输出到 test/results/ 目录下对应的 .txt 文件中。
