SCCP

稀疏条件常量传播（Sparse Conditional Constant Propagation），同时完成常量传播与死代码分析，通过三值格上的不动点迭代推断每个 SSA 值的常量性，然后替换常量指令并折叠条件分支。

格值模型

SCCP 使用三值格（Lattice）表示每个 SSA 值的已知信息：

格值含义典型场景
UNDEF尚未确定（可能是死代码）初始状态；无使用者或操作数未计算
CONSTANT编译期已知的常量值add i32 2, 3 → CONSTANT(5)
OVERDEF非恒定（运行时可变）函数参数、load、call 返回值

格值的偏序关系：UNDEF < CONSTANT < OVERDEF。值只能沿格向上移动（单调性保证收敛）。

Meet 运算

phi 节点使用 meet 运算合并来自不同前驱的格值：

meet — 格值合并规则
static LatticeValue meet(const LatticeValue &a, const LatticeValue &b) {
    if (a.isOverdef() || b.isOverdef()) return LV_OVERDEF;  // 任一 OVERDEF → OVERDEF
    if (a.isUndef()) return b;                               // UNDEF 不贡献信息
    if (b.isUndef()) return a;
    if (a.constVal() == b.constVal()) return a;              // 同一常量 → 保持
    return LV_OVERDEF;                                       // 不同常量 → OVERDEF
}

初始状态

初始化 — 常量已知，参数 OVERDEF，其余 UNDEF
// 所有指令初始化为 UNDEF（可能死代码或待计算）
for (auto *bb : func->basic_blocks_)
    for (auto *inst : bb->instr_list_)
        lattice[inst] = LV_UNDEF;
// 函数参数为 OVERDEF（调用者可能传任意值）
for (auto *ci : func->arguments_)
    lattice[ci] = LV_OVERDEF;
// ConstantInt 操作数在 getLat() 中直接返回常量值

不动点传播

SCCP 的核心是一个交替执行的两阶段迭代：

  1. 可达性分析：BFS 遍历基本块，但尊重已知常量分支——如果条件已为常量，只将确定跳转的目标块加入可达集合
  2. 格值更新：对每个可达块中的每条指令，重新计算格值，若有变化则继续迭代

最多迭代 10 轮，直到格值不再变化或达到上限。

条件分支感知可达性

BFS 中的常量分支感知
auto *br = dynamic_cast<BranchInst*>(t);
if (br && br->num_ops_ == 3) {  // 条件分支
    auto cond = getLat(br->get_operand(0));
    if (cond.isConstant()) {
        // 条件已知为常量：只将确定方向加入可达
        auto *taken = static_cast<BasicBlock*>(
            br->get_operand(cond.constVal() ? 1 : 2));
        reachable.insert(taken);
    } else {
        // 条件未知：两个方向都可达
        for (unsigned i = 1; i <= 2; i++)
            reachable.insert(static_cast<BasicBlock*>(br->get_operand(i)));
    }
}

这是 SCCP 相比普通常量传播的关键优势：不可达块中的指令不参与格值计算，其 phi 入边也被忽略，从而能发现更多常量。

Phi 节点的格值计算

phi 只对可达前驱的入边做 meet 运算：

Phi 格值计算
LatticeValue val = LV_UNDEF;
for (unsigned i = 0; i < phi->num_ops_; i += 2) {
    // 只考虑来自可达块的入边
    if (!reachable.count(static_cast<BasicBlock*>(phi->get_operand(i + 1))))
        continue;
    val = meet(val, getLat(phi->get_operand(i)));
}

传输函数

对每条指令，根据操作类型和操作数格值计算结果格值：

二元运算

支持 add、sub、mul、sdiv、srem、and、or、xor、shl、ashr。含两个特殊优化：

  • 乘零/与零：即使另一个操作数为 OVERDEF，x * 0 和 x & 0 仍为 CONSTANT(0)
  • 或全一：即使另一个操作数为 OVERDEF，x | -1 仍为 CONSTANT(-1)
evalBinOp — 二元运算求值
static int evalBinOp(Instruction::OpID op, int a, int b, bool &valid) {
    valid = true;
    switch (op) {
    case Instruction::Add:  return a + b;
    case Instruction::Sub:  return a - b;
    case Instruction::Mul:  return a * b;
    case Instruction::SDiv: return b ? a / b : (valid = false, 0);
    case Instruction::SRem: return b ? a % b : (valid = false, 0);
    case Instruction::And:  return a & b;
    case Instruction::Or:   return a | b;
    case Instruction::Xor:  return a ^ b;
    case Instruction::Shl:  return a << b;
    case Instruction::AShr: return a >> b;
    default: valid = false; return 0;
    }
}

整数比较 (icmp)

当两个操作数都是常量时，直接求值比较结果，支持 eq、ne、sgt、sge、slt、sle 六种谓词。

零扩展 (zext)

操作数为常量时直接传播（零扩展不改变非负常量的值）。

Select

条件为常量时只取确定分支的值；条件未知但两个分支值相同且为常量时，结果仍为该常量。

其他指令

call、load、store、alloca 等保守地标记为 OVERDEF。

应用阶段

不动点收敛后，分三步将分析结果写回 IR：

1. 替换常量指令

遍历格表，将格值为 CONSTANT 的非 phi、非终止指令替换为 ConstantInt，并删除原指令：

常量指令替换
for (auto &[val, lat] : lattice) {
    if (!lat.isConstant()) continue;
    auto *inst = dynamic_cast<Instruction*>(val);
    if (!inst || inst->is_phi() || inst->isTerminator()) continue;
    inst->replace_all_use_with(new ConstantInt(inst->type_, lat.constVal()));
    inst->parent_->delete_instr(inst);
}

2. 折叠条件分支

如果条件分支的格值为 CONSTANT，将条件 br 替换为无条件 br，并正确清理 phi 和 CFG 边：

条件分支折叠
// 确定跳转方向
auto *taken     = condLat.constVal() ? trueDest : falseDest;
auto *nonTarget = (taken == trueDest) ? falseDest : trueDest;
// 清理被抛弃目标的 phi 入边
if (nonTarget != taken)
    removeBBFromPhi(bb, nonTarget);
// 重建 CFG 边和终止指令
bb->remove_succ_basic_block(trueDest);
bb->remove_succ_basic_block(falseDest);
trueDest->remove_pre_basic_block(bb);
falseDest->remove_pre_basic_block(bb);
bb->delete_instr(br);
new BranchInst(taken, bb);

3. 删除不可达块（removeUnreachableBlocks）

折叠分支后，被切断的子图（包括不可达的自环/环，仅看前驱是否为空 发现不了它们）从入口不可达，必须立即删除。否则残留的不可达循环体的 phi 会被后续 pass 收缩成自引用指令（如 %v = sub %v, 5），使 InstCombine 等基于 "def 链有限"假设的改写无法终止（实测表现为 OOM）。

可达性沿 terminator 的基本块操作数传播而非 succ_bbs_ 链表——个别 pass 改写分支目标时会遗漏维护 pred/succ 链表，terminator 才是事实来源。 删除时先清理存活块中指向死块的链接与 phi 入边，再统一 remove_bb。

示例

示例 1：常量传播 + 死代码消除

优化前 — SysY 源码
int foo() {
    int a = 3;
    int b = 4;
    int c = a + b;    // 常量 7
    int d = c * 2;    // 常量 14
    return d;
}
优化前 — IR
define i32 @foo() {
label_entry:
  %a = add i32 0, 3
  %b = add i32 0, 4
  %c = add i32 %a, %b
  %d = mul i32 %c, 2
  ret i32 %d
}
格值推断过程
// 第 1 轮迭代：
%a = add i32 0, 3     → CONSTANT(3)
%b = add i32 0, 4     → CONSTANT(4)
%c = add i32 %a, %b   → CONSTANT(7)   （%a=3, %b=4）
%d = mul i32 %c, 2    → CONSTANT(14)  （%c=7, 2=2）
// 第 2 轮：无变化，收敛
优化后 — IR
define i32 @foo() {
label_entry:
  ret i32 14
}

所有中间计算被替换为常量 14，中间指令被删除。

示例 2：条件分支折叠

优化前 — IR
define i32 @bar() {
label_entry:
  %x = add i32 5, 3       ; CONSTANT(8)
  %cmp = icmp sgt i32 %x, 4  ; CONSTANT(1)  (8 > 4)
  br i1 %cmp, label %then, label %else

then:
  ret i32 100

else:                       ; 不可达！
  ret i32 0
}
优化后 — IR
define i32 @bar() {
label_entry:
  br label %then          ; 条件已折叠为无条件跳转

then:
  ret i32 100
}

%cmp 被推断为 CONSTANT(1)，条件分支被折叠，else 块不再可达（后续 DeadCodeDelete/CFGSimplify 会清除）。

示例 3：乘零特殊优化

优化前 — IR
define i32 @mulzero(i32 %x) {
label_entry:
  %a = mul i32 %x, 0      ; %x 是 OVERDEF，但乘零仍为 CONSTANT(0)
  %b = add i32 %a, 10     ; CONSTANT(10)
  ret i32 %b
}
优化后 — IR
define i32 @mulzero(i32 %x) {
label_entry:
  ret i32 10
}

尽管 %x 是 OVERDEF（函数参数，值未知），SCCP 利用了 x * 0 = 0 的代数恒等式，仍然推断出 %a 为 CONSTANT(0)。

示例 4：Phi 与可达性交互

优化前 — IR
define i32 @phi_demo() {
entry:
  br i1 1, label %A, label %B

A:
  br label %merge

B:                          ; 不可达（条件恒为 1）
  br label %merge

merge:
  %r = phi i32 [ 42, %A ], [ 99, %B ]
  ret i32 %r
}
格值推断
// B 不可达，phi 只考虑来自 A 的入边
%r = phi i32 [ 42, %A ]    → CONSTANT(42)  （meet 仅一个值）
优化后 — IR
define i32 @phi_demo() {
entry:
  br label %A

A:
  br label %merge

merge:
  ret i32 42
}

由于分支条件为常量 1，B 块不可达，phi 的 B 入边被忽略，%r 被推断为 42。
