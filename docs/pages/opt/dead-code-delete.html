DeadCodeDelete

死代码消除 Pass，删除无用指令、合并冗余基本块、消除平凡 phi 节点，通过不动点迭代持续清理 IR。

概览

DeadCodeDelete 对每个函数反复执行以下三个子变换，直到不再变化（不动点）：

子变换功能状态
死指令删除删除无使用者且无副作用的指令主用
控制流简化合并仅含无条件跳转且目标块仅有一个前驱的块对主用
平凡 phi 消除消除所有非自引用操作数相同的 phi主用
不可达块删除通过可达性分析删除不可达基本块已禁用
激进死代码消除从关键指令出发反向标记所有活跃指令，清除未标记指令已禁用

执行流程

DeadCodeDelete::execute — 不动点迭代
void DeadCodeDelete::execute(Module *module) {
    for (auto func : module->function_list_) {
        if (func->is_declaration()) continue;
        bool changed;
        do {
            changed = false;
            changed |= removeDeadInstructions(func);  // 主用
            changed |= simplifyCFG(func);             // 主用
            changed |= eliminateTrivialPhis(func);    // 主用
        } while (changed);
    }
}

三个子变换之间存在级联关系：死指令删除可能使 phi 变为平凡 phi，phi 消除后可能产生无使用者的指令，CFG 合并后可能暴露新的死代码，因此需要循环迭代直到不动点。

关键指令判定

在死代码分析中，关键指令（Critical Instruction）是指具有副作用或控制流语义、不能被随意删除的指令。所有其他指令只有在"有使用者"时才被视为活跃的。

isCriticalInstruction — 关键指令判定
bool DeadCodeDelete::isCriticalInstruction(Instruction *inst) {
    switch (inst->op_id_) {
        case Instruction::Ret:    return true;  // 函数返回
        case Instruction::Br:     return true;  // 分支跳转（控制流）
        case Instruction::Store:  return true;  // 内存写入（副作用）
        case Instruction::Call:   return true;  // 过程调用（可能有副作用）
        default:                  return false;
    }
}

add、sub、icmp、phi 等纯计算指令不属于关键指令，可以被安全删除（前提是无人使用）。

1. 死指令删除

扫描所有基本块的指令列表，删除无使用者且非关键的指令。这是最基础也最安全的死代码清理。

算法

removeDeadInstructions — 单遍扫描
bool DeadCodeDelete::removeDeadInstructions(Function *func) {
    bool changed = false;
    for (auto bb : func->basic_blocks_) {
        auto &instList = bb->instr_list_;
        for (auto it = instList.begin(); it != instList.end();) {
            Instruction *inst = *it;
            if (inst->use_list_.empty() && !isCriticalInstruction(inst)) {
                it = instList.erase(it);
                inst->remove_use_of_ops();  // 清理 def-use 链
                changed = true;
            } else {
                ++it;
            }
        }
    }
    return changed;
}

示例

优化前 — IR
define i32 @foo(i32 %x) {
label_entry:
  %dead1 = add i32 %x, 1      ; 无人使用
  %dead2 = mul i32 %dead1, 3  ; 唯一使用者 dead1 也是死代码
  %result = add i32 %x, 10    ; 被 ret 使用
  ret i32 %result
}
优化后 — IR
define i32 @foo(i32 %x) {
label_entry:
  %result = add i32 %x, 10
  ret i32 %result
}

%dead2 首先被删除（无使用者），这使得 %dead1 也失去使用者，在下一轮迭代中被删除。

2. 控制流简化

合并满足条件的"透传"基本块对：当前块仅含一条无条件跳转，且目标块只有当前块一个前驱。

合并条件

  • 当前块的终止指令是无条件 br（单操作数）
  • 目标块只有当前块一个前驱（succ->pre_bbs_.size() == 1）
  • 目标块首条指令不是 phi（避免 phi 合并的复杂性）

变换过程

  1. Phi 引用替换：将函数中所有 phi 对目标块的引用替换为对当前块的引用
  2. 指令移动：将目标块的所有非终止指令移动到当前块末尾
  3. 终止指令移动：将目标块的终止指令移动到当前块末尾
  4. CFG 更新：当前块继承目标块的所有后继，更新前后驱关系
  5. 删除目标块：从函数中移除并释放内存
simplifyCFG — 核心合并逻辑
bool DeadCodeDelete::simplifyCFG(Function *func) {
    bool changed = false;
    bool local_changed = true;
    while (local_changed) {
        local_changed = false;
        for (auto bb : func->basic_blocks_) {
            Instruction *term = bb->get_terminator();
            if (!term || term->op_id_ != Instruction::Br || term->num_ops_ != 1)
                continue;
            BasicBlock *succ = static_cast<BasicBlock *>(term->get_operand(0));
            if (succ->pre_bbs_.size() != 1 ||
                (!succ->instr_list_.empty() && succ->instr_list_.front()->is_phi()))
                continue;
            // ... 合并逻辑 ...
            local_changed = true; changed = true;
            break;  // 向量被修改，重新扫描
        }
    }
    return changed;
}

示例

优化前 — IR
define i32 @bar(i32 %x) {
label_entry:
  br label %middle          ; 无条件跳转

middle:                    ; 单一前驱，无 phi
  %a = add i32 %x, 1
  br label %done

done:
  %b = mul i32 %a, 2
  ret i32 %b
}
优化后 — IR（合并 entry + middle）
define i32 @bar(i32 %x) {
label_entry:
  %a = add i32 %x, 1
  br label %done

done:
  %b = mul i32 %a, 2
  ret i32 %b
}

middle 块被合并到 label_entry 中。注意：由于 middle 没有 phi 且是唯一前驱，可以安全合并。合并后 done 中 phi 对 middle 的引用也被替换为 label_entry。

3. 平凡 phi 消除

当一个 phi 节点的所有非自引用操作数都指向同一个值时，该 phi 是"平凡的"，可以被该值直接替换。

判定规则

平凡 phi 判定
Value *common = nullptr;
for (unsigned i = 0; i < phi->num_ops_; i += 2) {
    Value *v = phi->get_operand(i);
    if (v == phi) continue;  // 跳过自引用
    if (common == nullptr) {
        common = v;
    } else if (common != v) {
        common = nullptr;    // 不统一，非平凡
        break;
    }
}

级联消除

消除一个平凡 phi 后，引用它的其他 phi 可能也变为平凡的，因此使用工作表实现级联消除：

eliminateTrivialPhis — 工作表级联
bool DeadCodeDelete::eliminateTrivialPhis(Function *func) {
    std::set<PhiInst *> worklist;  // 初始包含所有 phi
    // ... 收集所有 phi 到 worklist ...
    while (!worklist.empty()) {
        auto phi = *worklist.begin();
        worklist.erase(worklist.begin());
        // 检查是否为平凡 phi
        if (common != nullptr) {
            phi->replace_all_use_with(common);
            phi->parent_->delete_instr(phi);
            // 将引用此 phi 的其他 phi 重新加入工作表
            for (auto *user : phiUsers)
                worklist.insert(user);
        }
    }
}

示例

优化前 — IR
define i32 @trivial(i32 %x) {
label_entry:
  br i1 1, label %then, label %else

then:
  br label %merge

else:
  br label %merge

merge:
  %a = phi i32 [ %x, %then ], [ %x, %else ]  ; 两边都是 %x，平凡
  %b = phi i32 [ %a, %then ], [ %a, %else ]  ; 两边都是 %a，平凡
  ret i32 %b
}
优化后 — IR
define i32 @trivial(i32 %x) {
  ; phi %a 被替换为 %x
  ; phi %b 被替换为 %x
  ret i32 %x
}

%a 先被消除（两个入边都是 %x），这使得 %b 的两个入边都变为 %x，于是 %b 也被级联消除。

4. 不可达块删除 （已禁用）

通过从入口块出发的可达性分析，找出所有不可达的基本块并删除。此功能当前在 execute() 中被注释掉，由 CFGSimplify 的 removeDeadBlocks 承担了类似职责。

算法

  1. 可达性分析：从入口块出发 BFS，通过终止指令中的基本块操作数遍历后继，标记所有可达块
  2. 收集不可达块：遍历函数所有块，未在可达集合中的即为不可达
  3. Phi 清理：在删除前，更新后继块中 phi 对即将删除块的引用
  4. 块删除：为不可达值生成零常量替换使用，清除指令，从函数中移除
deleteBasicBlock — 安全删除块
void DeadCodeDelete::deleteBasicBlock(BasicBlock *bb) {
    for (auto inst : bb->instr_list_) {
        if (inst->type_->tid_ != Type::VoidTyID) {
            auto *zero = new ConstantZero(inst->type_);
            inst->replace_all_use_with(zero);  // 不可达值 → 零常量
        }
    }
    for (auto inst : bb->instr_list_)
        inst->remove_use_of_ops();
    bb->instr_list_.clear();
    bb->parent_->remove_bb(bb);
    delete bb;
}

示例

不可达块场景
define i32 @unreachable() {
entry:
  ret i32 0

dead_block:                ; 无前驱，不可达
  %x = add i32 1, 2
  ret i32 %x
}

dead_block 没有任何前驱，从 entry 无法到达，将被删除。其中 %x 如有外部使用者，会被替换为 ConstantZero。

5. 激进死代码消除 （已禁用）

采用标记-清扫策略：从所有关键指令（ret/br/store/call）出发，反向遍历操作数依赖链，标记所有可达指令为"活跃"，未标记的指令即为死代码。此功能当前在 execute() 中被注释掉。

算法

aggressiveDCE — 标记-清扫
bool DeadCodeDelete::aggressiveDCE(Function *func) {
    std::set<Instruction *> live;
    markLiveInstructions(func, live);  // 从关键指令出发标记
    std::vector<Instruction *> dead_insts;
    for (auto bb : func->basic_blocks_)
        for (auto inst : bb->instr_list_)
            if (live.find(inst) == live.end() && !isCriticalInstruction(inst))
                dead_insts.push_back(inst);
    for (auto inst : dead_insts)
        if (inst->parent_) inst->parent_->delete_instr(inst);
    return !dead_insts.empty();
}

标记过程

markLiveInstructions — 反向依赖遍历
void DeadCodeDelete::markLiveInstructions(Function *func,
    std::set<Instruction *> &live) {
    std::queue<Instruction *> worklist;
    // 初始根集合：所有关键指令
    for (auto bb : func->basic_blocks_)
        for (auto inst : bb->instr_list_)
            if (isCriticalInstruction(inst)) {
                live.insert(inst);
                worklist.push(inst);
            }
    // 反向遍历操作数依赖
    while (!worklist.empty()) {
        Instruction *cur = worklist.front(); worklist.pop();
        for (unsigned i = 0; i < cur->num_ops_; ++i) {
            if (Instruction *op_inst = dynamic_cast<Instruction *>(cur->get_operand(i)))
                if (live.insert(op_inst).second)
                    worklist.push(op_inst);
        }
    }
}

示例

优化前 — IR
define void @adce_demo(i32 %x) {
entry:
  %a = add i32 %x, 1      ; 无使用者 → 死代码
  %b = mul i32 %x, 2      ; 被 store 使用 → 活跃
  store i32 %b, i32* @g
  %c = sub i32 %a, 3      ; 唯一使用者 %a 是死代码 → 也是死代码
  ret void
}
优化后 — IR
define void @adce_demo(i32 %x) {
entry:
  %b = mul i32 %x, 2
  store i32 %b, i32* @g
  ret void
}

从 store 和 ret 出发反向标记：store → %b → %x（参数，非指令）；ret 无操作数。%a 和 %c 不在活跃集合中，被清除。
