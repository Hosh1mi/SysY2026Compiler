InlineExpand

函数内联展开 Pass，基于成本/收益模型将小函数体复制到调用站点，消除调用开销并暴露跨函数优化机会。

概览

InlineExpand 对模块中每个函数的调用站点进行内联判定。通过加权指令计数估算成本，通过常量折叠收益估算收益，当收益大于成本且不超过代码膨胀阈值时执行内联。

内联阈值

常量值含义
INLINE_THRESHOLD80普通函数内联成本上限
INLINE_ALWAYS_THRESHOLD6极小函数始终内联
INLINE_RECURSIVE_THRESHOLD40递归函数内联成本上限
INLINE_COST_BUDGET300单函数总内联成本预算

内联判定流程

canInline 检查

  1. 大小检查：callee 指令数不超过 INLINE_THRESHOLD
  2. 极小函数：指令数 ≤ INLINE_ALWAYS_THRESHOLD 直接通过
  3. 调用站点数：callee 的调用站点数不能过多
  4. 成本/收益：加权指令计数（循环体乘数）与常量折叠收益比较
  5. 代码膨胀守卫：单函数总成本不超过 INLINE_COST_BUDGET

常量折叠收益估算

estimateConstantFoldBenefit 在调用站点将已知常量参数传入 callee，通过 RPO 前向传播追踪常量传播链，估算可消除的指令数（包括死块消除带来的级联收益）。

内联变换过程

performInline 执行实际内联：

  1. 块分裂：将 caller 的调用块分裂为 call_bb 和 after_bb
  2. callee 克隆：将 callee 的所有基本块复制到 call_bb 和 after_bb 之间，使用 ValMap 重映射
  3. alloca 提升：callee 的 alloca 指令提升到 caller 的 entry 块
  4. ret 处理：callee 的 ret 指令重写为 br after_bb，返回值通过 phi 节点传递
  5. call 替换：原 call 指令替换为 br callee_entry，所有对 call 结果的使用替换为 phi

递归内联

对于自递归函数，内联阈值降低为 INLINE_RECURSIVE_THRESHOLD（40），且仅在非递归调用站点内联一次，避免无限展开。
