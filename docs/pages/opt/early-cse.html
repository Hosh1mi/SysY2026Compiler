EarlyCSE

早期公共子表达式消除 Pass，沿支配树 DFS 遍历，使用哈希签名识别重复的纯计算指令、加载指令和纯函数调用，同时支持存储-加载转发和死存储检测。

概览

EarlyCSE 在 Mem2Reg 之后、其他优化之前执行，利用支配树的层级关系高效识别公共子表达式。支持五类消除：

类别说明
表达式 CSE消除重复的算术/逻辑/比较/转换指令
Load CSE消除对同一内存位置的重复加载
存储-加载转发将 store 的值直接转发给后续 load，避免内存访问
死存储检测删除被覆盖且未被读取的 store
纯函数调用 CSE消除对无副作用函数的重复调用

执行流程

EarlyCSE::execute — 通过 AnalysisManager 获取别名分析
PreservedAnalyses EarlyCSE::execute(Module *module, AnalysisManager &AM) {
    BasicAliasAnalysis &BAA = AM.getBasicAA(module);
    for (auto *func : module->function_list_) {
        if (!func->is_declaration())
            early_cse_on_function(func, BAA);
    }
    return PreservedAnalyses::none();
}
early_cse_on_function — 支配树 DFS 入口
static void early_cse_on_function(Function *func, const BasicAliasAnalysis &BAA) {
    if (func->basic_blocks_.empty()) return;
    auto &dom_children = func->getDominatorInfo().domChildren;
    BasicBlock *entry = func->basic_blocks_.front();
    auto loop_mods = analyze_loops(func);  // 循环感知
    std::unordered_map<ExprSignature, Value*> expr_map;
    std::vector<ActiveMemoryMod> activeMods;
    early_cse_dfs(entry, expr_map, dom_children, loop_mods, activeMods, BAA);
}

表达式签名

每条可消除指令被编码为 ExprSignature，用作哈希表的键：

ExprSignature 结构
struct ExprSignature {
    Instruction::OpID op_id;    // 操作类型
    Type*             ty;       // 结果类型
    unsigned          extra_op; // ICmp/FCmp 的谓词
    std::vector<Value*> ops;   // 操作数（常量已规范化）
};

交换律规范化：对可交换运算（add/mul/and/or/xor/icmp eq/ne），将指针地址较小的操作数放在前面，确保 add %a, %b 和 add %b, %a 产生相同签名。

常量规范化：同一类型同一值的常量共享同一个 Constant 对象，避免 add %x, 3 的两个 3 因对象不同而匹配失败。

1. 表达式 CSE

对"安全消除"的指令（算术、逻辑、比较、zext、位转换等），计算签名并在哈希表中查找。若已存在相同签名，用已有值替换；否则将当前指令加入哈希表。

可消除指令判定
inline bool is_safe_to_eliminate(Instruction *inst) {
    if (inst->is_void()) return false;     // store/br/ret/void call
    if (inst->is_call()) return false;
    if (inst->is_store()) return false;
    if (inst->is_alloca()) return false;
    if (inst->is_phi()) return false;
    return true;  // Binary/Unary/ICmp/FCmp/Load/ZExt/FPtoSI/SItoFP/BitCast/GetElementPtr
}

示例

优化前
  %a = add i32 %x, %y
  %b = mul i32 %a, 3
  %c = add i32 %x, %y    ; 与 %a 相同
  %d = mul i32 %c, 3     ; 与 %b 相同
优化后
  %a = add i32 %x, %y
  %b = mul i32 %a, 3
  ; %c 替换为 %a
  ; %d 替换为 %b

2. Load CSE

消除对同一内存位置的重复加载。Load 签名由两部分组成：

  • 指针操作数：规范化后的加载地址
  • 定义存储：最近一次修改该地址的 store/call（通过 activeMods 追踪）

只有指针相同且"定义存储"也相同时，两个 load 才被视为公共子表达式。

Store 失效

遇到 store 时，通过别名分析检查已缓存的 load 签名，将与 store 别名的 load 从哈希表中移除：

Store 导致的 Load 失效
// store 时，清除别名 load
for (auto si = expr_map.begin(); si != expr_map.end(); ) {
    if (si->first.op_id == Instruction::Load &&
        mayModPtr(BAA, inst, si->first.ops[0])) {
        si = expr_map.erase(si);  // 别名匹配，失效
    } else ++si;
}

汇合点清理

当基本块有多个前驱（控制流汇合点）时，清除所有缓存的 load 签名。因为一个兄弟分支中的 load 不支配另一个兄弟分支中的 load。

示例

优化前
  %v1 = load i32, i32* %p
  %x  = add i32 %v1, 1
  %v2 = load i32, i32* %p    ; 与 %v1 加载同一地址，中间无 store
优化后
  %v1 = load i32, i32* %p
  %x  = add i32 %v1, 1
  ; %v2 替换为 %v1

3. 存储-加载转发

在同一个基本块内，如果 store 到某地址后紧跟对同一地址的 load，直接将 store 的值作为 load 的结果，无需经过内存：

存储-加载转发逻辑
// load 时检查块内 store-load 转发
auto mem_it = local_mem.find(ptr);
if (mem_it != local_mem.end()) {
    inst->replace_all_use_with(mem_it->second.stored_val);
    to_delete.push_back(inst);
    continue;  // 不标记 has_been_read，store 可能成为死存储
}

示例

优化前
  store i32 42, i32* %p
  %v = load i32, i32* %p    ; 可直接用 42
优化后
  store i32 42, i32* %p
  ; %v 替换为常量 42，load 被删除

4. 死存储检测

在块内维护每个指针的最近 store 记录。当遇到对同一指针的新 store 时，如果旧 store 未被任何 load 读取过（has_been_read == false），则旧 store 是死存储：

死存储检测
auto mem_it = local_mem.find(ptr);
if (mem_it != local_mem.end() && !mem_it->second.has_been_read)
    to_delete.push_back(mem_it->second.store_inst);  // 旧 store 是死存储
local_mem[ptr] = {inst, val, false};  // 更新为新 store

示例

优化前
  store i32 1, i32* %p    ; 旧 store
  store i32 2, i32* %p    ; 新 store，旧 store 未被读取
优化后
  store i32 2, i32* %p    ; 旧 store 被删除

未知指针保护

当 store 的目标指针既不是 alloca 也不是全局变量时（如函数参数），保守地清除整个 local_mem 表，因为无法确定是否与其他指针别名。

5. 纯函数调用 CSE

对无副作用的纯函数（通过别名分析的 isPure 判定），如果同一函数以相同参数被调用多次，后续调用可用前次的结果替换：

纯函数判定 + CSE
auto *callee = dynamic_cast<Function*>(call->get_operand(call->num_ops_ - 1));
if (callee && !callee->is_declaration() && BAA.isPure(callee)) {
    ExprSignature sig = compute_signature(inst, empty_vn_map);
    // 查找或插入到 expr_map
}

非纯函数调用保守地清除所有缓存的 load，并将自身加入 activeMods。

示例

优化前（abs 是纯函数）
  %a = call i32 @abs(i32 %x)
  %b = call i32 @abs(i32 %x)    ; 相同参数，可消除
优化后
  %a = call i32 @abs(i32 %x)
  ; %b 替换为 %a

循环感知

EarlyCSE 通过分析自然循环，避免在循环迭代间错误地复用内存值。

自然循环分析

通过支配树检测回边（succ dom bb），收集循环体中的所有 store 和 call 指令。

循环头哨兵

进入循环头时，将循环内的 store/call 以 LOOP_SENTINEL 推入 activeMods。这使得 load 签名中的"定义存储"变为哨兵值，阻止了循环体外的 load 与循环体内的 load 匹配。

循环头哨兵注入
auto ls_it = loop_mods.find(bb);
if (ls_it != loop_mods.end()) {
    for (auto &mod : ls_it->second) {
        activeMods.push_back({mod.inst, LOOP_SENTINEL});
    }
}

支配树 DFS 与作用域恢复

EarlyCSE 沿支配树深度优先遍历。每个基本块处理完后，撤销本块对全局状态的修改，确保兄弟分支之间不会泄漏信息。

作用域恢复

DFS 尾部 — 撤销本块修改
// 撤销本块添加的签名
for (auto &sig : added_sigs)
    expr_map.erase(sig);
// 恢复本块删除的签名（仅当原指令不在当前块时）
for (auto &[sig, val] : removed_sigs)
    if (!inst_val || inst_val->parent_ != bb)
        expr_map[sig] = val;
// 恢复 activeMods
activeMods.resize(savedModSize);

这保证了：父块的信息向下传递（支配关系），但兄弟块之间互不干扰。
