DeadStoreEliminate

死存储消除 Pass，识别并删除冗余的"加载后原样存回"模式（store (load %p), %p），依赖别名分析保证指针别名关系的正确性。

概览

DeadStoreEliminate 识别一种特定的冗余存储模式：从内存位置加载一个值，然后又将该值存回同一位置。这种 store 不改变任何内存状态，可以安全删除。

执行流程

DeadStoreEliminate::execute
void DeadStoreEliminate::execute(Module *module) {
    BasicAliasAnalysis AA;
    AA.analyze(module);                // 全模块别名分析
    for (auto *func : module->function_list_) {
        if (!func->is_declaration())
            runOnFunction(func, AA);   // 每个函数独立处理
    }
}
runOnFunction — 收集 + 批量删除
bool DeadStoreEliminate::runOnFunction(Function *func,
                                       const BasicAliasAnalysis &AA) {
    std::vector<StoreInst *> toDelete;
    for (auto *bb : func->basic_blocks_)
        for (auto *inst : bb->instr_list_)
            if (auto *store = dynamic_cast<StoreInst *>(inst))
                if (isRedundantStore(store, AA))
                    toDelete.push_back(store);
    for (auto *store : toDelete)
        if (store->parent_) store->parent_->delete_instr(store);
    if (!toDelete.empty()) func->invalidateDominatorInfo();
    return !toDelete.empty();
}

先收集所有冗余 store，再批量删除，避免在遍历中修改指令列表。删除后失效支配树信息。

冗余存储判定

核心函数 isRedundantStore 判断一个 store 是否可以被消除。判定条件如下：

模式识别

目标模式：store (load %ptr), %ptr，即 store 的源操作数是一条 load 指令。

五项判定条件

#条件说明
1store 的源操作数是 LoadInst存储的值来自内存加载
2别名分析：storePtr 与 loadPtr 必须 MustAlias确保读写的确实是同一内存位置
3loadBB 支配 storeBB保证 load 一定在 store 之前执行
4同块时 load 必须在 store 之前同块内用 instBefore 检查指令顺序
5load 到 store 之间无指令修改目标指针通过 ModRef 分析检查中间是否有 store/call 修改了 storePtr
isRedundantStore — 完整判定逻辑
bool DeadStoreEliminate::isRedundantStore(StoreInst *store,
                                          const BasicAliasAnalysis &AA) {
    // 1. store 的源操作数必须是 load
    auto *load = dynamic_cast<LoadInst *>(store->get_operand(0));
    if (!load) return false;

    Value *storePtr = store->get_operand(1);
    Value *loadPtr  = load->get_operand(0);

    // 2. 别名分析：必须 MustAlias
    if (AA.alias(storePtr, loadPtr) != AliasResult::MustAlias)
        return false;

    // 3. 支配关系：load 所在块必须支配 store 所在块
    if (!func->dominates(loadBB, storeBB)) return false;

    // 4. 同块顺序检查
    if (loadBB == storeBB && !instBefore(load, store)) return false;

    // 5. 中间指令检查：load 到 store 的所有路径上不能有对 storePtr 的修改
    auto fromLoad = forwardReachableFrom(loadBB);
    auto toStore  = backwardReachableFrom(storeBB);
    for (auto *bb : func->basic_blocks_) {
        if (!fromLoad.count(bb) || !toStore.count(bb)) continue;
        // 只检查 load 之后到 store 之前的指令
        bool afterLoad = (bb != loadBB);
        for (auto *inst : bb->instr_list_) {
            if (inst == load)  { afterLoad = true; continue; }
            if (inst == store) break;
            if (!afterLoad)    continue;
            if (isModSet(AA.getModRefInfo(inst, storePtr)))
                return false;  // 中间有指令修改了 storePtr
        }
    }
    return true;
}

路径覆盖分析

第 5 个条件需要检查从 load 到 store 的所有可能路径。实现采用双向可达性交集：

  • forwardReachableFrom(loadBB) — 从 load 所在块沿后继方向 BFS，得到所有可达块
  • backwardReachableFrom(storeBB) — 从 store 所在块沿前驱方向 BFS，得到所有可达块
  • 两者的交集就是所有可能位于 load 到 store 之间的基本块

对交集中的每个块，只检查 load 之后（含 load 下一指令）到 store 之前（不含 store 本身）的指令。如果任何指令对 storePtr 有 Mod（写入）行为，则 store 不是冗余的。

示例

示例 1：简单冗余存储

优化前 — SysY 源码
int g;
void foo() {
    int tmp = g;   // load
    g = tmp;       // store 同一个值，冗余
}
优化前 — IR
@g = global i32 0

define void @foo() {
label_entry:
  %tmp = load i32, i32* @g   ; 从 @g 加载
  store i32 %tmp, i32* @g     ; 存回 @g，冗余
  ret void
}
优化后 — IR
define void @foo() {
label_entry:
  ret void
}

load 和 store 操作同一指针 @g，中间无任何修改，store 被消除。load 随后会被 DeadCodeDelete 清理（无使用者）。

示例 2：非冗余 — 中间有修改

不可消除的场景
define void @bar(i32* %p) {
label_entry:
  %v = load i32, i32* %p
  store i32 42, i32* %p       ; 中间修改了 %p 指向的内存
  store i32 %v, i32* %p       ; 不是冗余！%p 已被修改
  ret void
}

中间的 store i32 42, i32* %p 修改了 %p 指向的内存，因此最后的 store 不是简单的"原样存回"，不可消除。

示例 3：非冗余 — 别名不确定

不可消除的场景
define void @baz(i32* %p, i32* %q) {
label_entry:
  %v = load i32, i32* %p
  store i32 99, i32* %q       ; 可能修改 %p（如果 %p 和 %q 别名）
  store i32 %v, i32* %p       ; 不可消除：别名分析不确定
  ret void
}

别名分析无法确认 %p 和 %q 不别名（不是 MustAlias），因此中间的 store 可能修改了 %p 指向的内存，保守地保留最后的 store。

示例 4：跨块冗余存储

优化前 — IR
@g = global i32 0

define void @cross_bb(i32 %cond) {
entry:
  %v = load i32, i32* @g       ; load 在 entry 块
  br label %next

next:                           ; entry 支配 next
  store i32 %v, i32* @g        ; 中间无修改，冗余
  ret void
}
优化后 — IR
define void @cross_bb(i32 %cond) {
entry:
  %v = load i32, i32* @g
  br label %next

next:
  ret void
}

load 在 entry 块，store 在 next 块。entry 支配 next，且两个块之间无指令修改 @g，因此 store 被消除。

辅助函数

函数功能
instBefore(a, b)检查指令 a 是否在 b 之前（同块内线性扫描）
forwardReachableFrom(start)BFS 后继方向，返回所有可达块
backwardReachableFrom(start)BFS 前驱方向，返回所有可达块
AA.alias(a, b)别名分析：返回 MustAlias/NoAlias/MayAlias
AA.getModRefInfo(inst, ptr)查询指令对 ptr 的 Mod/Ref 行为
