ScalarExpandedInterchange

标量提升 + 循环交换的融合变换，将内层 reduction 通过临时数组展开后交换内外循环，改善访存局部性。

概览

LLVM 将 ScalarExpansion + LoopDistribution + LoopInterchange 拆为三个 pass；本编译器将其打包成一个变换，适用于内层带 reduction phi、收尾在 inner_exit 处写回数组的嵌套循环（如矩阵乘法）。

核心思想

对于形如 for(i) for(j) sum += A[i][j]*B[j] 的嵌套循环，如果内层循环（j 循环）包含 reduction，而最终结果写回到以外层 IV（i）为索引的数组，则：

  1. 将 reduction 标量提升为临时数组 tmp[P_bound]
  2. 交换内外循环顺序
  3. 用临时数组的 load/store 替代原来的标量 phi 累加

检测条件

结构要求

  • 内层循环 L 是最内层（children 为空），有父循环 P
  • L 与 P 都有规范 IV（init=0, step=+1, slt bound）
  • L 有 preheader、singleLatch、singleExit

Phi 要求

  • L.header 有 N+1 个 phi：L.IV + N 个 reduction phi（N ≥ 1）
  • 每个 reduction phi 的 init 在 P 外可见，latch 值在 L 内

访存要求

  • L body 不含 store/call
  • 所有 GEP 仿射、base loop-invariant，索引中只能出现祖先链上的 IV
  • L.singleExit 恰好 N 条 store，与 N 个 reduction phi 一一对应：store sum_phi → gep[base, 0, ..., P.IV]
  • P body 除 reduction store 外没有别的 store/call

合法性与收益判定

合法性

DependenceAnalysis.isInterchangeLegal 验证 P↔L 两层间没有跨循环的真依赖。每个 reduction 通过 scalar expansion 到 tmp[] 自然消除。

收益模型

CostModel.totalStride 比较 swap 前后所有 GEP 对内层 IV 的字节 stride 之和，严格变小才执行变换。

变换过程

变换后的 CFG 骨架
// 1. Clear loop: 初始化临时数组
for (jc = 0; jc < P_bound; jc++)
    tmp_i[jc] = sum_init_i;    // 对每个 reduction

// 2. 新外层循环（原 L）
for (nk = 0; nk < L_bound; nk++) {
    // 3. 新内层循环（原 P）
    for (nj = 0; nj < P_bound; nj++) {
        sum = load tmp[nj];
        // ... 原 L body 克隆（ValMap 重映射）...
        store sum_new, tmp[nj];
    }
}

// 4. Store-back loop: 写回最终结果
for (st = 0; st < P_bound; st++)
    C[...][st] = load tmp[st];

ValMap 重映射规则

原值映射到
L.IVnk_iv（新外层 IV）
P.IVnj_iv（新内层 IV）
sum_phi_iload tmp_i[nj_iv]
其他值identity（自动保留）

临时数组

每个 reduction 分配独立的全局变量 @__mm_tmp_<idx>_<size>，大小为 inner_dim（gep_store 最内一维的元素数）。

迭代策略

每次成功变换会改变 CFG，需要重建 LoopInfo / AffineAnalysis / DependenceAnalysis / CostModel。最多迭代 32 次以发现同一函数内的多个可变换嵌套循环。
