整体架构

编译器采用经典的三阶段架构：前端解析、中端优化、后端代码生成，通过 LLVM 风格的 SSA IR 连接各阶段。

编译流水线

从源文件到汇编的完整数据流：

.sy 源码
  │  Flex 词法分析
  ▼
Token 流
  │  Bison 语法分析
  ▼
AST（抽象语法树）
  │  Checker 语义检查
  ▼
AST（已校验）
  │  GenIR（Visitor 模式）
  ▼
SSA IR Module
  │  PassManager（优化 Pass）
  ▼
优化后 SSA IR
  │  Arm64CodeGen
  ▼
ARM64 汇编 (.s)
驱动入口

main.cpp 负责解析命令行参数、调用 yyparse() 解析源码、构建 Pass 流水线、配置后端并启动代码生成。

前端

词法与语法分析

使用 Flex（lexer.l）定义词法规则，Bison（parser.y）定义语法规则。 Bison 解析成功后直接构建 AST 节点，全局变量 root 指向根节点 CompUnitAST。

AST 设计

所有 AST 节点继承自 BaseAST，通过 Visitor 模式实现遍历。 Visitor 纯虚基类为每种节点定义 visit() 方法，Checker 和 GenIR 分别实现此接口。 

class BaseAST {
public:
    virtual ~BaseAST() = default;
    virtual void accept(Visitor &v) = 0;
};

class Visitor {
public:
    virtual void visit(CompUnitAST &) = 0;
    virtual void visit(FuncDefAST &) = 0;
    virtual void visit(StmtAST &) = 0;
    // ... 为每种 AST 节点定义 visit()
};

中端 IR

LLVM 风格容器层级

IR 采用四层容器结构，与 LLVM 对齐：

层级类职责
顶层Module全局变量列表、函数列表、基本类型单例、类型缓存
函数Function基本块列表、参数列表、惰性支配树
基本块BasicBlock指令链表、CFG 前驱/后继、活跃变量分析
指令Instruction40+ 种操作码、操作数列表、use-def 链

SSA 与 Use-Def 链

所有 IR 实体继承自 Value 基类，维护双向 use-def 链。每个 Use 记录 "谁在哪个操作数位置引用了我"，支持 replace_all_use_with() 全局替换，使优化 Pass 可以增量修改 IR。 

class Value {
    Type *type_;
    std::list<Use> uses_;  // 谁引用了我
public:
    void replace_all_use_with(Value *newVal);
    // ...
};

分析模块

分析模块为优化 Pass 提供数据支撑，由 AnalysisManager 统一管理缓存与失效：

分析类功能
别名分析BasicAliasAnalysisNoAlias / MayAlias / MustAlias + ModRef 信息
循环信息LoopInfo自然循环检测、嵌套树、preheader/latches/exits、规范归纳变量
标量演化ScalarEvolutionSCEV 表达式树（AddRecExpr），trip-count 计算
仿射分析AffineAnalysis将 Value 表示为仿射形式 \(c + \sum c_{iv} \cdot iv\)
依赖分析DependenceAnalysisGCD test 判断内存依赖方向向量
代价模型CostModel估算 GEP cache stride，判断 loop interchange 收益
惰性计算

AnalysisManager 按需计算分析结果，通过 PreservedAnalyses 位掩码实现增量失效，避免 Pass 执行时重复计算。

优化 Pass

Pass 基类与管理器

class Pass {
public:
    virtual std::string name() = 0;
    virtual void execute(Module *m) = 0;
    virtual void execute(Module *m, AnalysisManager &am) { execute(m); }
};

PassManager 维护线性 Pass 序列，按序执行。支持 --dump-ir 在每个 Pass 前后输出 IR， 以及 --verify-ir 校验 IR 完整性。

后端 ARM64

代码生成流程

Arm64CodeGen 遍历 Module 中的全局变量和函数，为每个函数执行以下步骤：

阶段组件说明
指令选择Arm64FuncContext将 SSA IR 指令翻译为 ARM64 汇编文本，分配栈槽位
PHI 处理preparePhi()在前驱块末尾插入 PHI 拷贝
分支融合tryEmitCSel()将 icmp+br 模式融合为 csel/ccmp 指令
寄存器分配Arm64RegAllocChaitin-Briggs 图着色，支持 phi 亲和性
块重排reorderBlocks()最大化 fallthrough，减少跳转
指令调度MachineScheduler局部调度隐藏延迟
PeepholepeepholeOptimize()汇编级模式匹配优化

机器指令表示

MachineInstr 携带文本汇编和元数据（MOpcode 分类、defs/uses 寄存器集、latency、 mayLoad/mayStore/setsFlags 标志），供调度和 Peephole 使用。

寄存器分配

采用 Chaitin-Briggs 乐观图着色算法，按活跃区间分池（整数/浮点/NEON）， 支持 spill cost 估算和 phi 亲和性约束。结果将 SSA Value 映射到物理寄存器（如 w19、s8、v10）。

关键设计模式

模式应用
Visitor 模式AST 遍历 — Checker 和 GenIR 通过 accept(Visitor&) 解耦遍历逻辑
Use-Def 链SSA IR — Value 基类维护双向引用，支持增量修改和全局替换
惰性分析缓存AnalysisManager 按需计算 + 位掩码失效；Function 惰性支配树
分阶段流水线优化 Pass 按功能分组，高优化等级多轮迭代
文本级后端直接生成汇编文本，MachineInstr 携带元数据供后处理使用
